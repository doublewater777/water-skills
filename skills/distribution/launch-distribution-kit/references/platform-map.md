# Launch Distribution Platform Map

Use this to choose and shape channels. Generate only the platforms that fit the product and launch, and rewrite for each platform instead of translating the same copy.

If the launch is compliance-sensitive or the platform rules may have changed, do a quick current check and save notes under `.builder/evidence/artifacts/YYYY-MM-DD-channel-style-research.md`.

## App Stores

### App Store / Google Play

Best for: app tools, mobile apps, paid apps, subscriptions.

Generate:

- title/name direction
- subtitle or short description
- full description
- what's new
- keyword themes
- screenshot caption themes

Style:

- precise and benefit-led
- avoid unverifiable superlatives
- match privacy, subscription, payment, and platform claims to actual implementation
- state subscription limits, account requirements, and data handling plainly

## China Platforms

### 微信公众号

Best for: narrative launch post, founder note, product thinking, longer context.

Generate:

- title options
- opening hook
- structured article outline
- full post or section draft
- CTA

Style:

- founder/product essay, not a generic ad
- title must match the body
- open with a concrete problem scene
- use clear section headings and one primary CTA
- explain what changed, who it is for, who it is not for, and what feedback is wanted

Avoid:

- "重磅", "紧急", "官方通知", "全网首发", or other official-sounding/title-bait wording unless literally true
- mismatch between title and body
- empty manifesto or broad productivity claims

Source signals:

- WeChat public-title governance reports: https://www.thepaper.cn/newsDetail_forward_26514412
- WeChat article skill signal: https://mcp.directory/skills/details/1290/wechat-article-writer

### 头条号 / 今日头条

Best for: broad practical utility, topical framing, search/discovery.

Generate:

- direct title options
- short practical article
- benefit bullets
- CTA

Style:

- broad-reader explanation
- short paragraphs
- concrete problem, concrete result
- make the utility visible without assuming the reader knows the product category

Avoid:

- sensational wording
- "神器" claims without proof
- exaggerated covers/titles or low-information posts

Source signals:

- Toutiao governance notice: https://www.toutiao.com/article/7506805798228509219/
- Title-bait enforcement summary: https://www.newrank.cn/article/detail/8444

### 小红书

Best for: lifestyle/productivity tools, visual before-after, personal workflow, scenario screenshots.

Generate:

- title hooks
- note body
- scenario bullets
- hashtag set
- screenshot/image caption ideas

Style:

- first-person or scenario-led
- write like a real usage note
- lead with a daily scene and show what changed
- include screenshot captions because the platform is visual
- use hashtags as discovery labels, not as filler

Avoid:

- fake experience
- hard-sell tone
- copied influencer style
- unsupported claims or undisclosed commercial/AI-generated content where disclosure is required

Source signals:

- Creator platform: https://creator.xiaohongshu.com/
- Public rule summary: https://www.zhanghaobang.cn/policy/xiaohongshu-content-policy-2026
- Platform overview: https://zh.wikipedia.org/wiki/%E5%B0%8F%E7%BA%A2%E4%B9%A6

### 即刻

Best for: indie app updates, builder notes, early-user community, direct feedback.

Generate:

- short post
- maker note
- concise feedback ask

Style:

- conversational
- honest about what was built and why
- one or two specific questions for early users
- okay to be niche; do not over-explain

Avoid:

- polished ad copy
- broad claims
- excessive hashtags

Source signals:

- Jike App Store positioning around niche circles and daily sharing: https://apps.apple.com/cn/app/%E5%8D%B3%E5%88%BBapp/id966129812

### 少数派

Best for: productivity apps, Apple ecosystem tools, workflow articles, thoughtful setup posts.

Generate:

- article pitch
- workflow narrative
- feature walkthrough
- screenshots needed
- limitation/feedback section

Style:

- polished, practical, workflow-focused
- show the actual setup and experience
- explain why the workflow matters, not just what features exist
- include limitations and concrete screenshots

Avoid:

- shallow launch announcement
- feature list without workflow context
- hiding rough edges

Source signals:

- Matrix writing/selection signal: https://sspai.com/post/39703

### V2EX

Best for: technical users, indie launches, developer/productivity tools.

Generate:

- post title
- concise body
- technical/product context
- feedback request

Style:

- humble, specific, non-marketing
- state affiliation directly
- explain the narrow problem and implementation context
- ask for concrete feedback from the relevant node/community

Avoid:

- sales tone
- repeated posting
- inflated claims
- generic cross-post copy

Source signals:

- V2EX topic-node community surface: https://www.v2ex.com/

### 朋友圈 / 微信群

Use only when the user explicitly asks for close-network distribution. Do not include by default for app-tool launch kits.

Best for: close network distribution and early user ask.

Generate:

- short personal version
- ask-for-feedback version

Style:

- human, direct, low polish
- personal relationship first, product second

### 抖音 / Bilibili

Use only when the user explicitly asks for short-video scripts or when the product has a strong visual demo.

Best for: visual demos, workflow transformations, app utilities with clear before-after.

Generate:

- 15-30 second script
- shot list
- caption
- CTA

Style:

- show the problem quickly
- demonstrate the payoff visually
- use real app screens, not abstract claims

## International Platforms

### Product Hunt

Best for: polished public launch with screenshots, maker engagement, and clear category.

Generate:

- tagline
- description
- maker comment
- first comment / FAQ
- launch day reply themes
- gallery/screenshot direction

Style:

- crisp category and benefit
- upbeat but proof-backed
- maker comment explains why the product exists
- describe what people can try today

Avoid:

- vague tagline
- no screenshots
- disappearing after launch

Source signals:

- Product Hunt launch guide: https://help.producthunt.com/en/articles/11082221-how-to-launch-on-product-hunt
- Posting guide: https://help.producthunt.com/en/articles/4849772-posting-on-product-hunt

### Hacker News

Best for: technical novelty, founder story, open-source, developer tools, or public tryable products with an implementation angle.

Generate:

- Show HN title only when there is something public and tryable
- direct body
- technical/problem details
- feedback questions

Style:

- non-promotional
- problem and implementation details first
- plain title, no editorialized hype

Avoid:

- launch hype
- generic marketing copy
- title bait

Source signals:

- HN guidelines: https://news.ycombinator.com/newsguidelines.html
- Show HN guidance: https://news.ycombinator.com/showhn.html

### Reddit

Best for: community-specific problem solving.

Generate:

- subreddit-specific title
- body adapted to the community
- disclosure sentence
- feedback question

Style:

- subreddit-native
- disclose affiliation
- ask for feedback
- adapt to each community's rules and norms

Avoid:

- cross-posting identical promo
- link-only posts
- ignoring subreddit rules

Source signals:

- Content policy: https://redditinc.com/policies/content-policy
- Spam guidance: https://support.reddithelp.com/hc/en-us/articles/360043504051-What-constitutes-spam

### X / Threads

Generate:

- short post
- long post
- thread

Style:

- one sharp idea per post
- include product category near the name
- lead with the new capability or user pain
- thread only if each post adds a distinct point

Avoid:

- too many claims in one post
- unexplained product name

Source signals:

- X posting help: https://help.x.com/en/using-x/how-to-post

### LinkedIn

Best for: professional workflow, founder narrative, B2B utility, builder lesson.

Generate:

- professional launch post
- founder lesson version
- work-context CTA

Style:

- professional workflow story
- product as example, not only pitch
- explain business, craft, or creator lesson
- less casual than X

Avoid:

- casual thread tone
- no professional relevance

Source signals:

- LinkedIn posting help: https://www.linkedin.com/help/linkedin/answer/a522433

### Email / Newsletter

Generate:

- subject lines
- preview text
- launch email
- update email

Style:

- clear why now
- one primary CTA
- short value statement before feature list
- do not bury the link

Avoid:

- multiple asks
- vague announcement without user value

Source signals:

- Mailchimp launch email guidance: https://mailchimp.com/resources/product-launch-email/

## Developer Channels

### GitHub Release / README

Best for: developer tools, open-source, integrations.

Generate:

- release notes
- README feature section
- migration notes

Style:

- factual
- setup and change details
- include compatibility, breaking changes, and upgrade steps when relevant

### Dev.to / 掘金 / CSDN

Best for: technical implementation stories and developer education.

Style:

- teach something
- include code, architecture, or tradeoffs
- keep product promotion secondary to the learning value
